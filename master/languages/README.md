# master/languages/ — translated label sets

Language variants of the labels, generated by the migrated language tool
(`tools/language-builder/`), never hand-edited. **English is NOT here** — the
English base (full labels + sheets + cuts + PDFs) lives in `master/`.

## What's here
- **`qya/` (Gray Elvish)** — the one **fully-built example**: labels + composed
  sheets + cuts + Bambu cuts + a full PDF mirror under `qya/pdf/`. This is the
  working showcase of a complete localized product.
- **All other languages** (`ar de emoji es fr it ja ko nl pl pt ru zh`) — the
  translated label SVGs only (the "subs"), plus a `GAPS.md`. **No finished
  sheets/PDFs are shipped** for these — the community builds those from the
  labels (`tools/custom_sheet.py` / `tools/build_language_dist.py`).

Each label carries `data-type-key` / `data-color-key` so it is deterministically
re-localizable from any language. Colour-name sizing follows the reference tier
rule; type names letter-fit. Font is `Arial,…` — a tweaker swaps it with
`tools/set_font.py` if needed.

## Posture (accepted)
English fallback for untranslated terms is **intentional at launch**, recorded
in each language's `GAPS.md` (never a silent fallback). Residual gaps are
genuine missing translations of specific Bambu colour names; the data
mismatches were fixed during pack preparation.

- **Gray Elvish (`qya`) is a community project** — completing its colour lexicon
  is community-contributed, not blocking launch.
- Machine-language colour gaps (`de`, `fr`, …) ship in English where the
  translator kept a proper noun. CJK/Arabic render but Arabic RTL + non-Latin
  font embedding are open (routed to the Adobe PDF pass).
